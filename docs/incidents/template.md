## 6. 恢复验证

分别记录以下结果，而不是只写“已恢复”：

1. 基础设施：节点是否 Ready、目标 Pod 是否 Ready、重启次数是否继续增长。
2. 服务发现：Service 的 EndpointSlice 是否重新包含就绪 Pod。
3. 监控：对应 Prometheus Target 是否 `UP`、告警从 `firing` 到 `resolved` 的时间；注意“Target UP”不等于业务成功。
4. 用户路径：用项目的冒烟脚本或浏览器实际验证登录、账户查询、总览和对账；如故障涉及资金写入，再核对幂等请求与双边流水。
5. 持续观察：记录观察时长及是否再发，未观察足够久就写“短时恢复，仍需观察”。
