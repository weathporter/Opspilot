# ADR-001：第一阶段采用模块化单体

- 状态：已接受
- 日期：2026-08-04

## 背景

OpsPilot需要同时展示Java业务开发、Linux运维、容器化、监控和故障处置能力。当前如果直接拆成多个微服务，会增加服务发现、调用治理和数据一致性的学习成本，反而削弱部署与排障主线。

## 决策

第一阶段保留一个Spring Boot进程和一个MySQL数据库，Java代码按照账户、转账、公共能力、配置和可观测性划分模块。部署脚本、Linux配置、容器配置与监控配置放在独立工程目录。

## 原因

1. 单进程便于理解一次请求从Nginx到数据库的完整路径。
2. 本地资源消耗较低，适合个人电脑反复进行故障演练。
3. 数据库事务能够真实演示资金转账的一致性。
4. 清晰模块边界允许后续按需拆分，而不是先制造分布式复杂度。

## 后续演进条件

只有出现独立扩缩容、独立发布、明显团队边界或不同可用性目标时，才评估拆分服务。拆分前先通过领域事件和接口隔离依赖，数据库拆分必须同步设计一致性方案。
